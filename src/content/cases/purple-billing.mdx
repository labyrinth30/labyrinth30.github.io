### 문제

정기결제 배치, 관리자 수동 재결제, 학부모 셀프 재결제는 모두 같은 구독을 청구할 수 있습니다. 관리자 API와 웹 API는 프로세스가 달라서 프로세스 안의 보호 장치로는 서로를 막을 수 없습니다. 락이 있어도 경로마다 이름이 다르면 마찬가지입니다.

### 맡은 일

결제 실패 안내에서 기존 체크아웃으로 넘어가 카드를 고르고 직접 재결제할 수 있게 만들었습니다. 이 진입점을 추가하면서 배치·관리자 경로와 같은 Redis 구독 락을 쓰도록 맞추고, 청구 로직은 기존 것을 재사용했습니다.

### 이렇게 한 이유

SETNX로 락을 잡은 다음 구독, 최근 실패 결제, 처리 중인 결제를 다시 조회했습니다. 락을 기다리는 사이에 다른 경로가 먼저 청구를 끝냈을 수 있어서입니다. 소유권, ACTIVE 상태, 첫 회차 여부, 처리 중인 결제, 재결제 기한을 다 확인한 뒤에만 청구합니다. 관리자 재결제는 CS 대응 때문에 기한 정책을 따로 뒀습니다.

락은 동시 진입을 막을 뿐입니다. TTL이 180초이고, PG 호출과 DB 저장을 원자적으로 묶어 주지는 않습니다. 청구 상태 재확인과 PG 결과 확인은 따로 챙겨야 합니다.

### 검증과 한계

재결제 가드와 알림 실패 처리 테스트를 작성했습니다. DEV 환경에서 직접 재청구 요청, PG 실패 응답, 화면 안내까지 확인했는데, DEV 상점 설정 때문에 결제 성공 케이스는 확인하지 못했습니다.
