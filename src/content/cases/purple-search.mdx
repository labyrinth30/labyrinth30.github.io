### 문제

관리자 주문 검색은 관련 회원·상품·결제 조건을 주문별 상관 검색으로 확인했습니다. 전체 기간으로 검색할 때 이 반복 비용이 커졌고, 과거 운영 기록에서 원번 검색의 count SQL은 4.73초가 걸렸습니다.

### 내 기여와 해결 방식

관련 테이블에서 검색어에 맞는 주문 ID를 **별도 UNION으로 먼저 수집**하도록 바꿨습니다. 주문 테이블의 직접 검색 조건은 유지했고, 검색 안내 문구와 연결되지 않았던 환불요청 검색도 손봤습니다. 한 SQL 안에 검색을 남기는 대신 왕복·ID 전달 비용을 감수하고 주문별 반복 계산을 줄였습니다.

### 과거 운영 기록 · 단발 SQL 측정

MySQL 8.0.42, 주문 **115,891행**, 전체 기간의 단발 기록입니다. 기존 count와 변경 후 ID 선별+count의 SQL 호출 시간을 비교했습니다.

| 검색 조건 | 기존 count | 변경 ID 선별+count |
| --- | ---: | ---: |
| 원번 | 4.73초 | 0.89초 |
| 무매칭 | 9.60초 | 0.56초 |
| 상품명 | 4.45초 | 1.16초 |
| 성씨 | 4.38초 | 0.88초 |
| 1글자 | 1.86초 | 1.95초 |

다섯 조건의 결과 건수는 같았습니다. **원번은 약 81.2% 감소**했고, 1글자는 90ms 늘었습니다. 원시 반복값과 데이터 스냅샷은 확보되지 않았으며 API·화면 전체의 개선율은 아닙니다.

### 새 로컬 검증 · 반복 SQL 측정

로컬 MySQL 9.3.0, Apple M1/16GiB, 활성 합성 주문 115,891행에 실제 개발 엔티티 메타데이터를 적용했습니다. warm cache에서 조건·버전별 warmup 2회를 제외하고 15회씩 순차·교대 실행했습니다.

| 검색 조건 | 기존 중앙값 (ms) | 변경 중앙값 (ms) |
| --- | ---: | ---: |
| 원번 | 2143.5 | 545.3 |
| 무매칭 | 2080.7 | 433.8 |
| 상품명 | 2174.2 | 643.9 |
| 성씨 | 1765.2 | 386.3 |
| 1글자 | 1925.1 | 630.6 |

로컬 합성 데이터에서 조건별 15회 측정한 SQL 호출 시간입니다. 과거 운영 측정과는 데이터·환경이 다른 별도 결과입니다.

### 검증 범위

활성 합성 데이터의 대표 다섯 조건에서 전체 주문 ID 순서·count와 페이지 대조가 통과했습니다. 동률의 주문 ID 정렬은 기존 팀 구현입니다. 실제 SQL 페이지 대조는 첫·마지막 경계이며, 전체 응답·엑셀 내용까지 비교한 것은 아닙니다.

**논리삭제 데이터에서는 기존 0건→변경 1~2건의 반례가 확인됐습니다.** 기존 QueryBuilder가 제외하던 삭제된 회원·주문상품·상품을 raw SQL이 제외하지 않아, 대표 조건의 일치를 완전한 결과 보존으로 확대할 수 없습니다. 구현은 수정하지 않았고 운영 영향 건수는 미집계입니다.

목록·count는 동일 필터를 쓰지만 상단 요약은 일부 상태·배송 필터를 전달하지 않습니다. 엑셀은 최대 5,000개 주문·선택 주문·상품행 확장·경로별 정렬 차이가 있어 전체 결과가 같다고 표현하지 않았습니다.
